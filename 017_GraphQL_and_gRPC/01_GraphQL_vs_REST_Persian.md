# جایگزین‌های API: مقایسه GraphQL و gRPC با REST

## این موارد چه هستند؟
اگرچه REST رایج‌ترین روش برای طراحی API است، اما توسعه بک‌اند مدرن اغلب از تکنولوژی‌های دیگری استفاده می‌کند که برای حل محدودیت‌های REST طراحی شده‌اند.

### ۱. گراف‌کیوال (GraphQL)
یک زبان کوئری (Query Language) برای API شماست که توسط فیس‌بوک توسعه داده شده است. برخلاف REST که در آن چندین اندپوینت (Endpoint) برای برگرداندن ساختارهای داده ثابت وجود دارد (مثلاً `/users` و `/posts`)، در GraphQL شما یک اندپوینت واحد (مثل `/graphql`) را در معرض دید قرار می‌دهید. کلاینت کوئری می‌فرستد و دقیقاً مشخص می‌کند چه داده‌ای را می‌خواهد، و سرور دقیقاً همان را برمی‌گرداند—نه بیشتر، نه کمتر.

**مشکلاتی که حل می‌کند:**
- **دریافت داده‌های اضافی (Over-fetching)**: دریافت داده‌هایی بیشتر از آنچه نیاز دارید (مثلاً دریافت کل آبجکت کاربر فقط برای پیدا کردن نام او).
- **دریافت داده‌های ناکافی (Under-fetching / مشکل N+1)**: مجبور شدن به ارسال چندین درخواست API برای دریافت داده‌های مرتبط (مثلاً واکشی یک کاربر، و سپس ارسال درخواست دوم برای دریافت پست‌های او).

### ۲. فریم‌ورک gRPC
فریم‌ورک gRPC یک چارچوب متن‌باز و با پرفورمنس بسیار بالا برای RPC (فراخوانی رویه از راه دور) است که توسط گوگل ایجاد شده است. این ابزار به جای JSON از **Protocol Buffers (Protobuf)** به عنوان زبان تعریف رابط (IDL) و همچنین فرمت تبادل پیام زیرساختی خود استفاده می‌کند.

**مشکلاتی که حل می‌کند:**
- **پرفورمنس (عملکرد)**: Protobuf باینری (صفر و یک) است، که باعث می‌شود حجم پیام‌ها بسیار کوچک‌تر شده و فرآیند Serialize/Deserialize کردن آن‌ها در مقایسه با JSON متنی بسیار سریع‌تر باشد.
- **تایپینگ سخت‌گیرانه (Strict Typing)**: قراردادهای API به طور دقیق در فایل‌های `.proto` تعریف می‌شوند که از روی آن‌ها، کدهای کلاینت و سرور در زبان‌های برنامه‌نویسی مختلف به صورت خودکار تولید می‌شود.

## چه زمانی و کجا از آن‌ها استفاده کنیم؟
- **REST**: برای APIهای عمومی همه‌منظوره، برنامه‌های ساده CRUD، و زمانی که کشینگ (Caching) اهمیت بسیار بالایی دارد، خوب است.
- **GraphQL**: بهترین گزینه برای برنامه‌های کلاینت پیچیده (مانند برنامه‌های موبایل یا SPAها) است که در آن‌ها انعطاف‌پذیری مورد نیاز است و می‌خواهید حجم داده‌ها و تعداد درخواست‌های شبکه را به حداقل برسانید.
- **gRPC**: ایده‌آل برای ارتباطات داخلی بین مایکروسرویس‌ها، جایی که به حداکثر پرفورمنس، تأخیر پایین (Low latency) و قراردادهای سخت‌گیرانه نیاز است.

## مثال‌ها

### مثال کوئری GraphQL
**درخواست کلاینت:**
```graphql
query {
  user(id: 1) {
    name
    email
    posts {
      title
    }
  }
}
```

**پاسخ سرور (JSON):**
```json
{
  "data": {
    "user": {
      "name": "John Doe",
      "email": "john@example.com",
      "posts": [
        { "title": "My first blog post" },
        { "title": "GraphQL is awesome" }
      ]
    }
  }
}
```

### مثال gRPC Protobuf (فایل `.proto`)
```protobuf
syntax = "proto3";

// The greeting service definition.
service Greeter {
  // Sends a greeting
  rpc SayHello (HelloRequest) returns (HelloReply) {}
}

// The request message containing the user's name.
message HelloRequest {
  string name = 1;
}

// The response message containing the greetings.
message HelloReply {
  string message = 1;
}
```
