# پروکسی مستقیم (Forward Proxy) در برابر پروکسی معکوس (Reverse Proxy)

## پروکسی چیست؟
پروکسی یک سرورِ واسطه (Middleman) است که بین کلاینت (کاربر) و سرور مقصد (اینترنت) قرار می‌گیرد. بسته به اینکه این واسطه قصد دارد هویتِ چه کسی را مخفی یا محافظت کند، به دو دسته پروکسی مستقیم و پروکسی معکوس تقسیم می‌شود.

## ۱. پروکسی مستقیم (Forward Proxy - مخفی‌کننده‌ی کلاینت)
- **مفهوم**: پروکسی مستقیم در جلوی **کلاینت (کاربر)** قرار می‌گیرد. وقتی شما می‌خواهید سایت `google.com` را باز کنید، درخواست شما اول به سرور پروکسی می‌رود. پروکسی از طرف شما درخواست را به گوگل می‌فرستد، جواب را می‌گیرد و به شما برمی‌گرداند.
- **چرا از آن استفاده می‌کنیم؟**
  ۱. **ناشناسی (Anonymity)**: گوگل فقط آدرس IP سرورِ پروکسی را می‌بیند، نه IP واقعی کامپیوترِ خانگی شما را (شبکه‌های خصوصیِ مجازی یا VPNها دقیقاً به همین شکل کار می‌کنند).
  ۲. **فیلتر کردن محتوا**: شرکت‌ها یا مدارس از Forward Proxy برای مسدود کردن دسترسی به سایت‌های خاص (مثل شبکه‌های اجتماعی) استفاده می‌کنند. اگر سایتِ مقصد در لیست سیاه باشد، پروکسی به سادگی از ارسال درخواست شما خودداری می‌کند.
  ۳. **کَش کردن (Caching)**: اگر ۵۰ دانش‌آموز در شبکه یک مدرسه یک صفحه یکسان از ویکی‌پدیا را درخواست کنند، پروکسی آن را فقط یک‌بار دانلود می‌کند و به ۴۹ نفر بعدی کپیِ ذخیره‌شده را نشان می‌دهد تا در مصرف اینترنت صرفه‌جویی شود.

### مثال برای پروکسی مستقیم (Squid)
اسکوئید (Squid) یک پروکسی مستقیم و متن‌باز معروف است. می‌توانید آن را به گونه‌ای پیکربندی کنید که فقط دسترسی به دامنه‌های خاصی را اجازه دهد.
```conf
# /etc/squid/squid.conf
acl allowed_domains dstdomain .google.com .wikipedia.org
http_access allow allowed_domains
http_access deny all
```

## ۲. پروکسی معکوس (Reverse Proxy - مخفی‌کننده‌ی سرور)
- **مفهوم**: پروکسی معکوس در جلوی **سرورهای بک‌اند** قرار می‌گیرد. وقتی یک کاربر سعی می‌کند سایت شما را باز کند، درخواست او مستقیماً به پروکسی معکوس (مثل Nginx، Cloudflare یا HAProxy) برخورد می‌کند. پروکسی تصمیم می‌گیرد که کدام سرور داخلیِ شما باید این درخواست را پردازش کند، جواب را از سرور می‌گیرد و به کاربر برمی‌گرداند.
- **چرا از آن استفاده می‌کنیم؟**
  ۱. **امنیت**: کاربر هرگز به طور مستقیم با دیتابیس یا سرورهای اصلی برنامه شما ارتباط برقرار نمی‌کند. آن‌ها فقط آدرس IP پروکسی معکوس را می‌بینند. این کار سرورهای داخلی شما را در برابر حملات مستقیم (مثل DDoS) محافظت می‌کند.
  ۲. **توزیع بار (Load Balancing)**: پروکسی معکوس می‌تواند ترافیکِ عظیمِ ورودی را به طور مساوی بین ۱۰ سرورِ مختلفِ بک‌اند تقسیم کند.
  ۳. **پایان‌دهی SSL (SSL Termination)**: به جای اینکه روی هر ۱۰ سرورِ بک‌اند گواهینامه SSL نصب کنید و پردازنده آن‌ها را درگیر کنید، گواهینامه SSL را فقط روی Reverse Proxy نصب می‌کنید. پروکسی ترافیک سنگینِ HTTPS را رمزگشایی می‌کند و ترافیکِ سبکِ HTTP را در داخل شبکه امن و خصوصیِ شما به سرورهای بک‌اند می‌فرستد.

### مثال برای پروکسی معکوس (Nginx)
انجین‌اکس (Nginx) به طور گسترده به عنوان پروکسی معکوس استفاده می‌شود. در اینجا یک پیکربندی ساده برای ارسال ترافیک از پورت ۸۰ به یک سرور بک‌اند که روی پورت ۳۰۰۰ در حال اجراست، آورده شده است.
```nginx
# /etc/nginx/sites-available/default
server {
    listen 80;
    server_name example.com;

    location / {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```
