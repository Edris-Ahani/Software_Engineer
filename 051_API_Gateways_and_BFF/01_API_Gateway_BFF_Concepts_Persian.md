# ای‌پی‌آی گیت‌وی (API Gateway) و الگوی BFF

## ای‌پی‌آی گیت‌وی (API Gateway) چیست؟
در معماری مایکروسرویس، شما ممکن است ۲۰ سرویس مختلف داشته باشید (مثل سرویس احراز هویت، کاربران، سفارشات، انبار و غیره). اینکه کلاینت فرانت‌اند مجبور باشد مستقیماً با هر ۲۰ سرویس ارتباط برقرار کند، یک روش بسیار بد (Bad Practice) است.
یک **API Gateway** به عنوان یک نقطه ورود واحد (یک Reverse Proxy) برای تمام درخواست‌های کلاینت عمل می‌کند.

**مزایای API Gateway:**
- **مسیریابی (Routing)**: درخواست‌های `/api/users` را به سرویس کاربران، و `/api/orders` را به سرویس سفارشات هدایت می‌کند.
- **مدیریت مسائل مشترک (Cross-cutting Concerns)**: کارهایی مثل اعتبارسنجی توکن‌های JWT (احراز هویت)، پایان‌دهی SSL، محدودیت نرخ درخواست (Rate Limiting) و مدیریت CORS را به صورت مرکزی انجام می‌دهد تا نیازی نباشد تک‌تک مایکروسرویس‌ها درگیر این کارها شوند.
- **تجمیع (Aggregation)**: می‌تواند همزمان چندین مایکروسرویس را فراخوانی کرده و پاسخ‌های آن‌ها را در یک آبجکت JSON ترکیب کرده و به کلاینت برگرداند.

## الگوی BFF (بک‌اند برای فرانت‌اند) چیست؟
با بزرگ شدن برنامه، ممکن است کلاینت‌های مختلفی داشته باشید: یک اپلیکیشن تحت وب، یک اپلیکیشن iOS و یک اپلیکیشن اندروید.
- یک اپلیکیشن موبایل ممکن است برای صرفه‌جویی در مصرف پهنای‌باند و باتری، به دیتای کمتری نیاز داشته باشد.
- یک اپلیکیشن وب ممکن است به دیتای پیچیده و تجمیع‌شده‌ای برای نمایش در داشبورد نیاز داشته باشد.

به جای اینکه یک API Gateway مرکزی را مجبور کنیم تا منطق پیچیده فرمت کردن داده‌ها را برای هر پلتفرم به دوش بکشد، **الگوی BFF (Backend for Frontend)** پیشنهاد می‌کند که *چندین* API Gateway کوچکتر بسازیم—که هر کدام دقیقاً متناسب با یک نوع فرانت‌اند سفارشی شده‌اند (مثلاً یک `BFF برای وب` و یک `BFF برای iOS`).
تیم فرانت‌اند معمولاً مدیریت BFF مخصوص به خود را بر عهده می‌گیرد، که به آن‌ها اجازه می‌دهد داده‌های بک‌اند را دقیقاً به شکلی که رابط کاربری (UI) آن‌ها نیاز دارد، قالب‌بندی کنند.
