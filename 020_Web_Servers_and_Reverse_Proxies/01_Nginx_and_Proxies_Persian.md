# سرورهای وب و پروکسی‌های معکوس (Reverse Proxies)

## این موارد چه هستند؟
اگرچه سرورهای برنامه (مانند Node.js/Express یا Python/Django) منطق تجاری (Business Logic) برنامه را هندل می‌کنند، اما معمولاً در پشت یک **سرور وب (Web Server)** یا **پروکسی معکوس (Reverse Proxy)** قرار می‌گیرند تا کارهای سنگین مربوط به ترافیک خام اینترنت را مدیریت کنند.

## پروکسی معکوس در برابر پروکسی معمولی (Forward Proxy)
- **پروکسی معمولی (Forward Proxy)**: در مقابل *کلاینت* قرار می‌گیرد و اطمینان حاصل می‌کند که هیچ سرور مقصدی مستقیماً با آن کلاینت خاص ارتباط برقرار نمی‌کند (مانند فیلترشکن‌ها یا شبکه‌های داخلی شرکت‌ها). این پروکسی از *کلاینت* محافظت می‌کند.
- **پروکسی معکوس (Reverse Proxy)**: در مقابل *سرور وب* قرار می‌گیرد و اطمینان حاصل می‌کند که هیچ کلاینتی مستقیماً با سرورهای بک‌اند شما ارتباط برقرار نمی‌کند. این پروکسی از *سرور* محافظت می‌کند.

## پروکسی معکوس چه مشکلاتی را حل می‌کند؟
۱. **تعدیل بار (Load Balancing)**: توزیع درخواست‌های ورودی در بین چندین سرور برنامه (بک‌اند).
۲. **خاتمه‌دهی SSL (SSL Termination)**: رمزگشایی درخواست‌های HTTPS ورودی تا سرور برنامه شما فقط با HTTP ساده (بدون رمزنگاری) سر و کار داشته باشد و در مصرف پردازنده (CPU) صرفه‌جویی شود.
۳. **کشینگ (Caching)**: ذخیره محتوای استاتیک (مانند تصاویر، فایل‌های CSS و JS) و ارائه مستقیم آن‌ها به کاربر بدون اینکه حتی نیازی به درگیر کردن سرور بک‌اند باشد.
۴. **فشرده‌سازی (Compression)**: فشرده‌سازی فایل‌های خروجی (مثلاً با Gzip یا Brotli) برای کاهش پهنای باند و افزایش سرعت بارگذاری.
۵. **امنیت**: پنهان کردن وجود و ویژگی‌های سرورهای بک‌اند شما. آن‌ها می‌توانند به عنوان یک فایروال برنامه وب (WAF) عمل کنند.

## Nginx
انجین‌اکس (**Nginx**) محبوب‌ترین سرور وب متن‌باز است که به عنوان پروکسی معکوس، Load Balancer و کش HTTP استفاده می‌شود.

### مثال‌ها

**یک پیکربندی پایه برای پروکسی معکوس Nginx:**
```nginx
server {
    # Listen on port 80 (HTTP)
    listen 80;
    server_name mywebsite.com;

    location / {
        # Forward all requests to the local Node.js app running on port 3000
        proxy_pass http://localhost:3000;
        
        # Pass necessary headers to the backend
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```
