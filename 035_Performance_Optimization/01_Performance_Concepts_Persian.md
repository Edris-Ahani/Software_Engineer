# بهینه‌سازی پرفورمنس (Performance Optimization)

## چیست؟
بهینه‌سازی پرفورمنس فرآیند اصلاح یک سیستم نرم‌افزاری است تا کارآمدتر عمل کند و سریع‌تر اجرا شود. در مهندسی بک‌اند، این کار معمولاً به معنای کاهش زمان پاسخ‌دهی (Latency) و افزایش ظرفیت پردازش درخواست‌ها (Throughput / Requests per second) است.

## گلوگاه‌های رایج پرفورمنس و راه‌حل‌های آن‌ها

### ۱. مشکل کوئری‌های N+1 (The N+1 Query Problem)
- **مشکل**: شما برای دریافت لیست ۱۰۰ کاربر، به دیتابیس کوئری می‌زنید (۱ کوئری). سپس، برای هر کاربر، یک حلقه اجرا می‌کنید و دوباره برای دریافت پست‌های او به دیتابیس کوئری می‌زنید (۱۰۰ کوئری). مجموع: ۱۰۱ کوئری. این کار پرفورمنس دیتابیس شما را نابود می‌کند.
- **راه‌حل**: استفاده از `JOIN` در SQL، یا استفاده از قابلیت "Eager Loading" در ORMها برای واکشی تمام کاربران و پست‌هایشان تنها با ۲ کوئری.

### ۲. عدم استفاده از ایندکس‌گذاری (Lack of Indexing)
- **مشکل**: جستجوی یک آدرس ایمیل خاص در یک جدول دیتابیس با میلیون‌ها ردیف بدون داشتن ایندکس، دیتابیس را مجبور به انجام "اسکن کامل جدول" (Full Table Scan - یعنی بررسی تک‌تک ردیف‌ها) می‌کند.
- **راه‌حل**: اضافه کردن `INDEX` دیتابیس روی ستون‌هایی که مکرراً در بخش `WHERE` کوئری‌ها استفاده می‌شوند. این کار یک جستجوی خطی و کند O(n) را به یک جستجوی درختی فوق‌سریع O(log n) تبدیل می‌کند.

### ۳. انتقال بیش از حد داده‌ها
- **مشکل**: ارسال فایل‌های بزرگ JSON شامل داده‌هایی که کلاینت اصلاً به آن‌ها نیازی ندارد، یا ارسال متن فشرده‌نشده روی شبکه.
- **راه‌حل**:
  - استفاده از **صفحه‌بندی (Pagination)** (مثلاً برگرداندن ۲۰ آیتم در هر درخواست به جای ۱۰۰۰۰ آیتم).
  - فعال کردن **فشرده‌سازی Gzip/Brotli** روی سرور وب یا API Gateway.
  - استفاده از **GraphQL** یا فیلدهای انتخابی (Sparse fields) برای بازگرداندنِ فقط داده‌های درخواست‌شده.

### ۴. محاسبات سنگین روی ترد اصلی (Main Thread)
- **مشکل**: در محیط‌های تک‌نخی (Single-threaded) مانند Node.js، انجام محاسبات سنگین ریاضی یا پردازش فایل، Event Loop را مسدود می‌کند و باعث می‌شود تمام درخواست‌های کاربران دیگر متوقف بمانند (Hang کنند).
- **راه‌حل**: انتقال کارهای سنگین به **Background Workers** (مثلاً با استفاده از Redis و BullMQ) یا ایجاد پروسس‌های فرزند (Child Processes) جداگانه.

### ۵. سرویس‌دهی فایل‌های استاتیک از بک‌اند
- **مشکل**: استفاده از سرور Node.js یا Python برای ارائه تصاویر، ویدیوها و فایل‌های CSS، چرخه‌های ارزشمند CPU و پهنای باند را هدر می‌دهد.
- **راه‌حل**: استفاده از شبکه توزیع محتوا (**CDN**) مانند Cloudflare یا AWS CloudFront برای کش کردن و ارائه فایل‌های استاتیک از سرورهای لبه (Edge servers) که از نظر فیزیکی به کاربر نزدیک‌تر هستند.

## پروفایلینگ (Profiling)
قبل از اینکه چیزی را بهینه‌سازی کنید، باید آن را اندازه‌گیری کنید. **پروفایلینگ** عمل تحلیل اجرای برنامه شماست تا دقیقاً ببینید CPU در کجا وقت می‌گذراند و حافظه رم در کجا اشغال می‌شود. هرگز حدس نزنید چه چیزی کُند است؛ برای اثبات آن از ابزارهای پروفایلینگ (مانند `--prof` در Node.js، ابزار Py-Spy یا New Relic) استفاده کنید.
