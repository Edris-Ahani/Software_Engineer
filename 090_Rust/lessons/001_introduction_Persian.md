# ۰۰۱ ـ Rust چیست و چه کاربردی دارد؟

[فهرست دوره](../README_Persian.md) · [درس بعد: نصب](002_installation_Persian.md)

Rust یک زبان کامپایل‌شونده با type system ایستا است. قبل از اجرا، کد به برنامهٔ هدف تبدیل می‌شود. ویژگی تعیین‌کننده‌اش مالکیت و قرض‌گرفتن داده است: کامپایلر در کد safe بررسی می‌کند reference به حافظهٔ آزادشده نداشته باشی و دسترسی هم‌زمان ناسازگار ایجاد نکنی. برای این کار به garbage collector عمومی و اجباری نیاز ندارد.

«بدون GC» به معنی «بدون تخصیص حافظه» نیست: `String`، `Vec` و `Box` می‌توانند حافظهٔ heap بگیرند. خروج از scope و `Drop` منابع را آزاد می‌کنند. `Rc` و `Arc` از reference counting استفاده می‌کنند و چرخهٔ strong reference می‌تواند نشت حافظه ایجاد کند.

## چه مسئله‌هایی را حل می‌کند؟

| حوزه | مسئلهٔ عملی | دلیل مناسب‌بودن Rust | هزینه یا محدودیت |
| --- | --- | --- | --- |
| ابزار خط فرمان | جست‌وجوی لاگ یا تبدیل فایل حجیم | فایل اجرایی بومی و کنترل مصرف حافظه | ساخت برای هر target |
| سرویس شبکه | تعداد زیاد اتصال منتظر I/O | async و کنترل تخصیص | پیچیدگی runtime و cancellation |
| زیرساخت و سیستم | موتور ذخیره‌سازی، agent و parser | کنترل layout و هزینهٔ منابع | نیاز به دانش سیستم‌عامل |
| WebAssembly | محاسبهٔ سنگین در مرورگر | خروجی WASM و اتصال به JavaScript | هزینهٔ عبور داده از مرز JS/WASM |
| Embedded | firmware روی میکروکنترلر | `no_std` و کنترل سخت‌افزار | ابزار و target وابسته به برد |
| کتابخانهٔ مشترک | انتقال بخش داغ یک برنامه به کد بومی | C ABI و کنترل خطا | قرارداد دقیق ownership در FFI |

سه پروژهٔ این دوره نمونهٔ کوچک CLI، منطق کسب‌وکار و سرویس HTTP هستند. برای کاربردهای رسمی زبان، [وب‌سایت Rust](https://rust-lang.org/) و [حوزه‌های کاربرد](https://www.rust-lang.org/what) را ببین.

## مقایسهٔ تصمیم‌محور

با Python و JavaScript می‌توان prototype را سریع‌تر نوشت؛ Rust پیش از اجرا خطاهای بیشتری را آشکار می‌کند، اما ownership در شروع زمان می‌خواهد. Go مدل ساده‌تری برای بسیاری از سرویس‌ها دارد و GC بخشی از مدل اجرای آن است. C/C++ کنترل سطح پایین دارند؛ Rust بخش زیادی از قراردادهای استفادهٔ حافظه را در type system بیان می‌کند. انتخاب نهایی به تیم، کتابخانه‌ها، مصرف منابع و نیاز ارتباط با کد موجود وابسته است.

Rust تضمین نمی‌کند برنامه deadlock، خطای منطقی، SQL injection، مصرف نامحدود حافظه یا race در سطح منطق کسب‌وکار نداشته باشد. `unsafe` و وابستگی‌های FFI نیز مرزهای مهم تضمین ایمنی هستند.

## مدل اجرای اولین برنامه

```text
Source files -> rustc checks types and borrowing -> native executable -> OS
Cargo -> dependency resolution + build orchestration + tests + docs
rustup -> toolchains + targets + components
```

این سه ابزار نقش‌های متفاوت دارند: برای شروع روزانه بیشتر با Cargo کار می‌کنی. پس از نصب، مثال هزینهٔ ارسال را از ریشهٔ دوره اجرا کن:

```bat
cmd /c cargo run -p rust-lessons --bin 001_basics
```

خروجی اول `Total: 600, shipping: 80` است. محاسبهٔ هزینه ورودی‌های نوع‌دار دارد و خروجی آن عدد است؛ درس‌های بعد نشان می‌دهند چگونه حالت نامعتبر را در type و خطا مدل کنیم.

**تمرین:** یک ابزار واقعی از کار روزانه‌ات انتخاب کن. ورودی، خروجی، محدودیت حافظه و نیازهای کتابخانه‌ای آن را بنویس. توضیح بده چرا Rust برای آن مناسب است یا چرا هزینهٔ یادگیری‌اش فعلاً توجیه ندارد.
