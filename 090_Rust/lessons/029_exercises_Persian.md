## تمرین‌های توسعهٔ مستقل

**الف ـ CLI شمارش match:** گزینهٔ count اضافه کن. در حالت count فقط عدد چاپ شود؛ خطای فایل همچنان exit ۲ بماند. اگر از default mode به count می‌روی، شمارهٔ خط را با تعداد match اشتباه نگیر.

**ب ـ موجودی چندقلمی:** رزرو چند SKU باید همه‌یا‌هیچ باشد. قبل از اعمال تغییرات، همهٔ validationها و جمع مبلغ را کنترل کن؛ SKU تکراری در یک درخواست را نیز تعیین تکلیف کن. API تک‌قلمی فعلی نباید در شکست قلم دوم، قلم اول را کم کرده باشد.

**ج ـ محدودیت طول خط:** در CLI برای هر خط سقف byte تعریف کن. استفاده از `read_line` و بررسی اندازه پس از تخصیص بزرگ کافی نیست؛ خواندن bounded و رفتار عبور از حد را طراحی کن.

**د ـ API پایدار:** repository دیتابیس، migration، transaction و idempotency اضافه کن. سپس restart و دو درخواست concurrent برای آخرین موجودی را تست کن. این تمرین به پایگاه دادهٔ مستقل نیاز دارد و جزو پروژهٔ حافظه‌ای حاضر نیست.

**ه ـ تحلیل آیندهٔ async:** توضیح بده چرا timeout روی حلقهٔ CPU بدون yield الزاماً کار نمی‌کند و چرا drop کردن JoinHandle با drop کردن future یکسان نیست.

برای تمرین‌های توسعه، چندین طراحی معتبر وجود دارد؛ [پاسخ‌نامه](030_solutions_Persian.md) روش حل و invariantها را می‌دهد، نه ادعای وجود یک نسخهٔ کامل برای هر نیاز تولیدی.
