# امنیت وب و OWASP Top 10

## چیست؟
امنیت وب به معنای محافظت از وب‌سایت‌ها، برنامه‌های وب و APIها در برابر تهدیدات سایبری و دسترسی‌های غیرمجاز است. لیست **OWASP Top 10** یک سند استاندارد آگاهی‌بخشی برای توسعه‌دهندگان است که نمایانگر مهم‌ترین و خطرناک‌ترین آسیب‌پذیری‌های امنیتی در برنامه‌های تحت وب است.

## مفاهیم کلیدی و آسیب‌پذیری‌ها (نمونه‌هایی از OWASP Top 10)
۱. **نقص در کنترل دسترسی (Broken Access Control)**: مهاجمان می‌توانند با تغییر URL، دستکاری وضعیت داخلی برنامه، یا استفاده از ابزارهای حمله API، کنترل‌های دسترسی را دور بزنند و به داده‌های سایر کاربران دسترسی پیدا کنند.
   - *راه‌حل*: پیاده‌سازی کنترل دسترسی مبتنی بر نقش (RBAC)، مسدود بودن پیش‌فرض دسترسی‌ها (Deny by default) و اعتبارسنجی مجوز در سمت سرور برای هر درخواست.
۲. **تزریق (Injection - مثل SQL Injection)**: داده‌های نامعتبر کاربر به عنوان بخشی از یک فرمان یا کوئری به مفسر (مثلا دیتابیس) ارسال می‌شود. داده‌های مخرب می‌توانند مفسر را فریب دهند تا دستورات ناخواسته‌ای را اجرا کند.
   - *راه‌حل*: استفاده از کوئری‌های پارامترایز شده (Prepared Statements) یا ORMها. هرگز رشته‌ها را برای ساخت کوئری‌های SQL به هم متصل نکنید.
۳. **اسکریپت‌نویسی بین‌سایتی (Cross-Site Scripting - XSS)**: مهاجمان اسکریپت‌های مخرب سمت کلاینت (معمولا جاوا اسکریپت) را به صفحات وبی که توسط کاربران دیگر مشاهده می‌شوند تزریق می‌کنند. این کار باعث دزدیده شدن کوکی‌ها، تغییر ظاهر سایت یا هدایت کاربران به سایت‌های مخرب می‌شود.
   - *راه‌حل*: رمزگذاری/فرار (Encoding/Escaping) داده‌های نامعتبر قبل از نمایش در صفحه HTML. فریم‌ورک‌هایی مثل React به صورت پیش‌فرض از این حمله جلوگیری می‌کنند.
۴. **جعل درخواست بین‌سایتی (CSRF)**: حمله‌ای که کاربر نهایی را مجبور می‌کند تا اقدامات ناخواسته‌ای را در برنامه‌ای که در حال حاضر در آن احراز هویت شده (لاگین کرده) انجام دهد.
   - *راه‌حل*: استفاده از توکن‌های Anti-CSRF و ویژگی SameSite در کوکی‌ها.

## سایر مفاهیم مهم امنیتی برای بک‌اند
- **CORS (Cross-Origin Resource Sharing)**: یک مکانیزم امنیتی در مرورگرهاست که مانع از این می‌شود یک صفحه وب به دامنه‌ای غیر از دامنه‌ای که خودش از آن لود شده درخواست بفرستد، مگر اینکه سرور صراحتاً با هدرهای CORS این اجازه را داده باشد.
- **هشینگ (Hashing) در برابر رمزنگاری (Encryption)**: رمزهای عبور همیشه باید **هش** شوند (یک‌طرفه و غیرقابل بازگشت، با استفاده از الگوریتم‌هایی مثل bcrypt) و هرگز نباید رمزنگاری (دو‌طرفه) شوند یا به صورت متن ساده (Plain text) ذخیره شوند.

## چه مشکلاتی را حل می‌کند؟
- **نشت داده‌ها (Data Breaches)**: از سرقت داده‌های حساس کاربران (رمزهای عبور، کارت‌های اعتباری، اطلاعات شخصی) جلوگیری می‌کند.
- **حفظ اعتبار**: شرکت را از عواقب ویرانگر قانونی و روابط عمومی ناشی از هک شدن محافظت می‌کند.

## مثال‌ها

### مثال آسیب‌پذیری تزریق SQL در Node.js
```javascript
// VERY BAD: Vulnerable to SQL Injection
// If user inputs:  jane@example.com' OR '1'='1
// The query becomes: SELECT * FROM users WHERE email = 'jane@example.com' OR '1'='1' (Returns all users!)
const email = req.body.email;
const query = `SELECT * FROM users WHERE email = '${email}'`;
db.execute(query);

// GOOD: Using Parameterized Queries
// The database treats the input strictly as data, not as executable code.
const email = req.body.email;
const query = `SELECT * FROM users WHERE email = $1`;
db.execute(query, [email]);
```
