# محدودسازی نرخ درخواست‌های API (Rate Limiting)

## چیست؟
محدودسازی نرخ (Rate Limiting) یک استراتژی برای محدود کردن ترافیک شبکه است. این روش مشخص می‌کند که یک کاربر چقدر می‌تواند یک عمل خاص را در یک بازه زمانی معین تکرار کند (مثلاً تعداد دفعات تلاش برای ورود به حساب کاربری). اصطلاح Throttling نیز مشابه است، اما به جای مسدود کردن کامل درخواست‌ها، ممکن است فقط سرعت پردازش آن‌ها را کاهش دهد.

## چرا مهم است؟
۱. **جلوگیری از حملات DDoS و سوءاستفاده**: بدون محدودیت نرخ، یک کاربر مخرب می‌تواند میلیون‌ها درخواست در ثانیه به سرور شما ارسال کند و آن را از کار بیندازد.
۲. **محافظت در برابر حملات Brute Force**: از حدس زدن رمز عبور توسط هکرها با امتحان کردن هزاران ترکیب در دقیقه جلوگیری می‌کند.
۳. **کنترل هزینه‌ها**: اگر API شما یک سرویس پولی شخص ثالث (مانند OpenAI یا سرویس پیامک) را فراخوانی می‌کند، یک حلقه بی‌نهایت (Infinite loop) در کد کاربر می‌تواند هزاران دلار برای شما هزینه تراشی کند.
۴. **انصاف (Fairness)**: تضمین می‌کند که یک کاربرِ واحد، تمام منابع CPU و دیتابیس سرور را مصرف نمی‌کند تا برنامه برای سایر کاربران کند نشود.

## الگوریتم‌های رایج
۱. **سطل توکن (Token Bucket)**: یک سطل با تعداد مشخصی توکن به کاربر داده می‌شود. هر درخواست یک توکن مصرف می‌کند. سطل با سرعت ثابتی دوباره پر می‌شود. اگر سطل خالی باشد، درخواست رد می‌شود (با خطای HTTP 429 Too Many Requests).
۲. **سطل نشتی (Leaky Bucket)**: مشابه سطل توکن است، با این تفاوت که درخواست‌ها همیشه با یک سرعت کاملاً ثابت و یکنواخت پردازش می‌شوند.
۳. **پنجره زمانی ثابت (Fixed Window)**: تعداد درخواست‌ها را در یک بازه زمانی ثابت (مثلاً از ساعت ۰۰:۰۰ تا ۰۰:۰۱) ردیابی می‌کند. اگر به سقف مجاز برسد، کاربر باید تا شروع پنجره زمانی بعدی صبر کند.

## چگونه پیاده‌سازی می‌شود؟
Rate Limiting معمولاً در یکی از این لایه‌ها پیاده‌سازی می‌شود:
- **دروازه‌های API (API Gateways) / Load Balancerها**: (مانند Nginx، AWS API Gateway یا Cloudflare). این بهترین مکان برای مسدود کردن ترافیک است.
- **لایه اپلیکیشن (Application Level)**: با استفاده از یک دیتابیس درون‌حافظه‌ایِ سریع مانند **Redis**. در محیط Node.js، میدل‌ور (Middleware) معروفی به نام `express-rate-limit` بسیار پرکاربرد است.
