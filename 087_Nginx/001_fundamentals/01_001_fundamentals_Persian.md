# 001 — نقش Nginx و مسیر پردازش درخواست

<div dir="rtl">

## هدف یادگیری
قبل از تغییر تنظیمات، بتوانید جایگاه Nginx را توضیح دهید. پیش‌نیاز: آشنایی اولیه با URL، آدرس IP و مفهوم پردازش.

مرورگر با DNS آدرس دامنه را پیدا می‌کند، اتصال TCP می‌سازد (در HTTP/3 از QUIC استفاده می‌شود)، برای HTTPS مذاکرهٔ TLS انجام می‌دهد و سپس درخواست HTTP می‌فرستد. Nginx ممکن است فایل را از دیسک بخواند، پاسخ تغییر مسیر بدهد یا اتصال دیگری به برنامه باز کند. درست بودن DNS به‌تنهایی به معنی باز بودن پورت یا معتبر بودن گواهینامه نیست.

</div>


```text
Browser → DNS → Nginx :443 → application :3000 → database
                       └──→ /srv/www/assets/logo.svg

GET /api/orders?limit=10 HTTP/1.1
Host: shop.example.test
```

<div dir="rtl">

## مفاهیمی که باید از هم تشخیص دهید

| نقش | مسئولیت | مثال |
| --- | --- | --- |
| وب‌سرور | ارائهٔ فایل و پاسخ HTTP | فایل `/assets/logo.svg` |
| پراکسی معکوس | فرستادن درخواست به برنامه | مسیر `/api/orders` به Node.js |
| توزیع‌کنندهٔ بار | انتخاب یکی از چند نمونهٔ برنامه | `app1` یا `app2` |
| کش HTTP | استفادهٔ مجدد از پاسخ مجاز | فهرست عمومی کالاها |
| برنامه | منطق کسب‌وکار و کنترل دسترسی | بررسی مالک سفارش |

Nginx به‌تنهایی کد برنامهٔ JavaScript، Python یا PHP را اجرا نمی‌کند. برای PHP معمولاً PHP-FPM و FastCGI استفاده می‌شود. برای جلوگیری از دسترسی مستقیم به بک‌اند باید محدودیت شبکه نیز داشته باشید.

</div>

## اولین آزمایش
آزمایشگاه Docker را طبق [راهنمای اجرا](../00_HOW_TO_RUN_Persian.md) بالا بیاورید و این دستورها را بزنید. هنگام اجرای مستقیم دستورهای curl در PowerShell ویندوز از `curl.exe` استفاده کنید.

</div>


```bash
curl -i http://localhost:8080/
curl -i http://localhost:8080/api/hello?name=nginx
curl -i http://localhost:8080/healthz
```

<div dir="rtl">

## تحلیل نتیجه
مسیر `/` یک صفحهٔ ایستا است. `/api/hello` یک JSON شامل نام بک‌اند، زمان و مسیر دریافتی برمی‌گرداند. `/healthz` را خود Nginx پاسخ می‌دهد؛ بنابراین پاسخ ۲۰۰ این مسیر **سلامت برنامه یا دیتابیس را ثابت نمی‌کند**. بررسی آمادگی باید وابستگی‌های لازم برای پذیرش ترافیک را هم پوشش دهد.

## معماری و محدودیت‌ها
پردازش master تنظیمات و workerها را مدیریت می‌کند. workerها با ورودی/خروجی رویدادمحور اتصال‌های زیادی را مدیریت می‌کنند؛ کار پردازشی همچنان هزینه دارد. یک درخواست پراکسی ممکن است هم اتصال کلاینت و هم اتصال به بک‌اند مصرف کند. کلاینت کند، دیسک، حافظه، تعداد file descriptor و ظرفیت برنامه همگی مهم‌اند.

## تمرین و پاسخ
اگر `/healthz` پاسخ ۲۰۰ ولی `/api/hello` پاسخ ۵۰۲ بدهد، آیا اول باید DNS را بررسی کرد؟ خیر؛ درخواست به Nginx رسیده است. پردازش برنامه، پورت، شبکه و error log را بررسی کنید و روی نمودار مشخص کنید کدام اتصال شکست خورده است.
