# مکانیزم CORS (اشتراک منابع متقابل مبدأ)

## قانون Same-Origin Policy (SOP)
به دلایل امنیتی، مرورگرهای وب قانونی به نام **Same-Origin Policy (سیاست هم‌مبدأ)** را به شدت اجرا می‌کنند. این یعنی یک اپلیکیشن جاوااسکریپتی که روی `https://my-website.com` اجرا می‌شود، مطلقاً حق ندارد به دامنه دیگری مانند `https://api.another-site.com` درخواست API بفرستد. اگر این قانون وجود نداشت، یک وب‌سایت مخرب که شما باز کرده‌اید می‌توانست در پس‌زمینه با استفاده از کوکی‌های ذخیره‌شده‌ی شما، به سایت بانک شما درخواست بفرستد!

## CORS چیست؟
CORS مکانیزمی است که به سرورها اجازه می‌دهد قانونِ سخت‌گیرانه‌ی SOP را *کمی شُل کنند*. این سیستم از هدرهای خاصِ HTTP استفاده می‌کند تا به مرورگر بگوید: "اجازه دادن به `my-website.com` برای خواندن داده‌های من کاملاً امن است."

## نحوه کار (درخواست Preflight)
وقتی فرانت‌اندِ شما سعی می‌کند یک درخواستِ پیچیده (مثل `POST` یا `PUT` حاوی فایل JSON) را به یک دامنه‌ی دیگر بفرستد، مرورگر به طور خودکار درخواست را متوقف کرده و یک بررسیِ پیش‌پرواز (Preflight) انجام می‌دهد:
۱. **مرورگر می‌پرسد**: مرورگر یک درخواست `OPTIONS` به سرورِ API می‌فرستد و می‌پرسد: "آیا شما تمایل دارید یک درخواست `POST` را از سمت `my-website.com` بپذیرید؟"
۲. **سرور پاسخ می‌دهد**: سرورِ API هدرِ خاصی را برمی‌گرداند: `Access-Control-Allow-Origin: https://my-website.com` (یعنی بله، اجازه دارد).
۳. **درخواست اصلی**: مرورگر می‌بیند که مجوز صادر شده است و تازه در این لحظه، درخواستِ اصلیِ `POST` را به همراه اطلاعات JSON ارسال می‌کند.

## خطای معروف CORS
اگر در کنسول مرورگر خود خطای ترسناک `Blocked by CORS policy` را دیدید، تقریباً همیشه به این معناست که **سرور بک‌اند شما** هدرهای مجازِ CORS را به درستی تنظیم نکرده است. شما به هیچ‌وجه نمی‌توانید این خطا را از داخل کدهای فرانت‌اند حل کنید (مگر اینکه از یک سرور Proxy واسط استفاده کنید).
