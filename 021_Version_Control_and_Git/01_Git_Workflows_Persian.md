# کنترل نسخه و استراتژی‌های Git

## چیست؟
سیستم‌های کنترل نسخه (VCS) تغییرات اعمال شده روی یک فایل یا مجموعه‌ای از فایل‌ها را در طول زمان ثبت می‌کنند تا بتوانید بعداً به نسخه‌های خاصی بازگردید. **گیت (Git)** پراستفاده‌ترین سیستم کنترل نسخه توزیع‌شده در دنیای امروز است.

## استراتژی‌های برنچینگ در Git (Workflows)
برای کار موثر در یک تیم، توسعه‌دهندگان روی یک گردش‌کار (Workflow) خاص توافق می‌کنند. رایج‌ترین آن‌ها عبارتند از:

### ۱. Feature Branch Workflow
- برنچ `main` (یا `master`) همیشه حاوی کدی است که آماده برای پروداکشن است.
- هر زمان که یک توسعه‌دهنده کار روی یک ویژگی جدید یا رفع باگ را شروع می‌کند، یک برنچ جدید از روی `main` می‌سازد (مثلاً `feature/login-page`).
- وقتی کار تمام شد، آن‌ها یک Pull Request (PR) یا Merge Request (MR) باز می‌کنند تا کدشان را دوباره در `main` ادغام (Merge) کنند.

### ۲. گردش‌کار Gitflow
- یک مدل ساختاریافته‌تر و پیچیده‌تر است.
- از دو برنچ دائمی استفاده می‌کند: `main` (تاریخچه پروداکشن) و `develop` (برنچ یکپارچه‌سازی برای ویژگی‌های جدید).
- از برنچ‌های موقت برای این موارد استفاده می‌کند: `feature/*` (منشعب از develop)، `release/*` (منشعب از develop وقتی آماده پروداکشن است) و `hotfix/*` (منشعب مستقیم از main برای رفع باگ‌های فوری پروداکشن).

### ۳. توسعه مبتنی بر تنه (Trunk-Based Development)
- تمام توسعه‌دهندگان کدهای خود را چندین بار در روز در یک برنچ مرکزی (`trunk` یا `main`) ادغام می‌کنند.
- ویژگی‌های ناتمام اغلب با استفاده از **Feature Flags** (تغییردهنده‌های وضعیت ویژگی) پنهان می‌شوند تا زمانی که کاملاً آماده شوند.
- این روش برای محیط‌های CI/CD به شدت توصیه می‌شود زیرا از "جهنم ادغام" (Merge Hell) جلوگیری می‌کند.

## چه مشکلاتی را حل می‌کند؟
- **همکاری تیمی**: به ده‌ها یا صدها توسعه‌دهنده اجازه می‌دهد تا به طور همزمان روی یک پایگاه کد (Codebase) یکسان کار کنند، بدون اینکه تغییرات یکدیگر را بازنویسی (Overwrite) کنند.
- **تاریخچه و بازگشت به عقب (Rollback)**: اگر یک ویژگی جدید باعث خرابی سرور پروداکشن شود، می‌توانید فوراً به کامیت (Commit) سالم قبلی بازگردید.
- **بازبینی کد (Code Review)**: ساختار Pull Requestها ایجاب می‌کند که کدها قبل از تأثیر گذاشتن روی محصول اصلی، توسط سایر همکاران بررسی شوند.

## دستورات کلیدی
```bash
git clone <url>      # Downloads a repository
git checkout -b <br> # Creates a new branch and switches to it
git commit -am "Msg" # Stages all modified files and commits them
git push origin <br> # Pushes the branch to the remote server
git rebase main      # Reapplies your branch's commits on top of main
```
