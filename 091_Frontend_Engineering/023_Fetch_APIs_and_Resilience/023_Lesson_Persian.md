# 023 — دریافت API و تاب‌آوری

[English](./023_Lesson_English.md) · [مسیر دوره](../README_Persian.md) · [راهنمای اجرا](../RUNNING_Persian.md)

## مفهوم و سازوکار

کلاینت API پیش از تبدیل پاسخ به دادهٔ دامنه، وضعیت، محتوا و schema را بررسی می‌کند. loading، موفقیت، خالی، شکست و لغو را جدا مدل کنید. timeout به signal لغو نیاز دارد؛ مسابقهٔ promise زمان‌سنج به‌تنهایی درخواست را متوقف نمی‌کند.

تلاش مجدد بودجهٔ محدود، backoff و اغلب jitter می‌خواهد. خواندن تکرارپذیر با شکست موقت را تکرار کنید، نه همهٔ شکست‌ها؛ 400 یا خطای اعتبارسنجی با تکرار بهتر نمی‌شود. تکرار خودکار mutation به پشتیبانی idempotency سرور نیاز دارد. REST منبع و GraphQL طرح با فیلد منتخب ارائه می‌دهد و GraphQL ممکن است با HTTP 200 هم داده و هم خطا بدهد. هر دو به قرارداد صریح صفحه‌بندی، مجوز و کش نیاز دارند.

## خطاهای رایج

لغو ناشی از جست‌وجوی تازه را خطای ترسناک نشان ندهید. parse موفق JSON ساختار payload را معتبر نمی‌کند.

## تمرین و معیار پذیرش

بارگذار JSON بسازید که 404 و رکورد نامعتبر را رد کند؛ پاسخ قدیمی، لغو و 503 قابل تلاش مجدد را شبیه‌سازی کنید.

## راهنمای حل

response.ok و ورودی unknown را بررسی کنید، timeout اعمال کنید و فقط وضعیت مجاز را با تعداد تلاش کم تکرار کنید.
