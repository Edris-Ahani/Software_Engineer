# 052 — طراحی سیستم فرانت‌اند

[English](./052_Lesson_English.md) · [مسیر دوره](../README_Persian.md) · [راهنمای اجرا](../RUNNING_Persian.md)

## مفهوم و سازوکار

طراحی سیستم را با کاربر، جریان کار، مقیاس، محدودیت دستگاه و شبکه و نیاز غیرعملکردی قابل سنجش آغاز کنید. مالکیت داده، قرارداد API، رندر، عمر state، کش، دسترس‌پذیری، بازیابی شکست، استقرار و مشاهده‌پذیری را مشخص کنید. مسیر بحرانی نیت کاربر تا نتیجهٔ تأییدشده را رسم کنید.

microfrontend انتشار مستقل تیم را ممکن می‌کند، اما یکپارچگی runtime، وابستگی تکراری، routing، هویت، یکدستی طراحی و بازیابی هماهنگ را دشوار می‌کند. وقتی مرز سازمانی هزینه را توجیه می‌کند از آن استفاده کنید. backend-for-frontend ترکیب API را اختصاصی و اسرار را سرور نگه می‌دارد، ولی سرویس عملیاتی دیگری اضافه می‌کند. tradeoff را با سناریوی واقعی بیان کنید، نه فقط نام معماری.

## خطاهای رایج

پیش از نیازسنجی با global state یا microfrontend شروع نکنید. نمودار بدون مسیر شکست کامل نیست.

## تمرین و معیار پذیرش

بازار چندزبانه برای موبایل کند با کاتالوگ جست‌وجوپذیر، سبد، پرداخت هویتی و موجودی زنده طراحی کنید.

## راهنمای حل

کاتالوگ عمومی کش‌پذیر را از پرداخت خصوصی جدا، id عملیات پایدار تعریف، موجودی قدیمی را مدیریت و هزینهٔ شروع و تعامل را بودجه‌بندی کنید.
