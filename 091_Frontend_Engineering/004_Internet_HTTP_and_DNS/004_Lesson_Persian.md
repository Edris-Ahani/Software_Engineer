# 004 — اینترنت، DNS و HTTP

[English](./004_Lesson_English.md) · [مسیر دوره](../README_Persian.md) · [راهنمای اجرا](../RUNNING_Persian.md)

## مفهوم و سازوکار

ناوبری ممکن است شامل جست‌وجوی DNS، ایجاد اتصال، مذاکرهٔ TLS، درخواست HTTP، تغییر مسیر و دریافت منابع دیگر باشد. HTTP/2 جریان‌ها را روی یک اتصال چندگانه می‌کند؛ HTTP/3 از QUIC استفاده می‌کند. تأخیر و حجم مستقل‌اند؛ کاهش حجم JavaScript پاسخ کند سرور را درمان نمی‌کند.

درخواست را با روش، URL، سرآیند و بدنه بخوانید. GET برای دریافت، POST معمولاً برای ایجاد یا اجرای عملیات، PUT برای جایگزینی نمایش منبع و PATCH برای تغییر جزئی است. کد وضعیت جزئی از قرارداد است: 401 مربوط به احراز هویت، 403 رد دسترسی، 404 نبود منبع و 429 محدودیت نرخ است. origin از طرح، میزبان و پورت تشکیل می‌شود. CORS خواندن پاسخ توسط API مرورگر از مبدأ دیگر را کنترل می‌کند و مجوزدهی سرور نیست.

## خطاهای رایج

fetch برای 404 نیز resolve می‌شود؛ response.ok را بررسی کنید. موفقیت preflight مجاز بودن دسترسی کاربر را ثابت نمی‌کند.

## تمرین و معیار پذیرش

در Network یک سند و یک درخواست API را بررسی کنید؛ آغازکننده، زمان‌ها، وضعیت، سرآیند کش و حجم انتقال را بنویسید.

## راهنمای حل

زمان اتصال، انتظار سرور و دانلود را جدا کنید. پیش از تشخیص گلوگاه، با کش خاموش و شبکهٔ محدود آزمایش را تکرار کنید.
