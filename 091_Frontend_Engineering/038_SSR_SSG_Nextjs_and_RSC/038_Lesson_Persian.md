# 038 — SSR، SSG، Next.js و RSC

[English](./038_Lesson_English.md) · [مسیر دوره](../README_Persian.md) · [راهنمای اجرا](../RUNNING_Persian.md)

## مفهوم و سازوکار

CSR رابط را در مرورگر، SSR به‌ازای درخواست و SSG از پیش HTML می‌سازد. revalidation محتوای پیش‌ساخته را با راهبرد صریح تازگی به‌روز می‌کند. براساس شخصی‌سازی، تازگی، کش‌پذیری و تعامل برای هر route تصمیم بگیرید، نه یک حالت برای کل محصول.

hydration رفتار کلاینت را به HTML سازگار سرور متصل می‌کند. تاریخ نامعین، مقدار تصادفی و شرط مخصوص مرورگر می‌تواند mismatch بسازد. React Server Component روی سرور اجرا می‌شود و ممکن است JavaScript کلاینت را کم کند، اما با SSR متفاوت است. مرز client کد لازم و props سریال‌شدنی را به مرورگر می‌فرستد. server action یا function باید مانند endpoint عمومی mutation ورودی و مجوز را بررسی کند. API و پیش‌فرض کش در نسخه‌های فریم‌ورک فرق می‌کند.

## خطاهای رایج

HTML خصوصی را با کلید عمومی کش نکنید و تصور نکنید "use client" یعنی کامپوننت هیچ مشارکتی در رندر سرور ندارد.

## تمرین و معیار پذیرش

برای بازاریابی، کاتالوگ عمومی، داشبورد حساب و نشانگر موجودی زنده روش رندر انتخاب و تازگی و حریم خصوصی را توضیح دهید.

## راهنمای حل

محتوای عمومی پایدار را پیش‌ساخته، کاتالوگ مشترک را revalidate، پاسخ هویتی را جدا و موجودی زنده را با کانال کلاینت یا خواندن بدون کش به‌روز کنید.
