# 051 — معماری فرانت‌اند

[English](./051_Lesson_English.md) · [مسیر دوره](../README_Persian.md) · [راهنمای اجرا](../RUNNING_Persian.md)

## مفهوم و سازوکار

معماری وابستگی را طوری سازمان می‌دهد که دامنهٔ تغییر قابل مدیریت باشد. وقتی قابلیت‌ها مستقل تغییر می‌کنند کد را براساس قابلیت کسب‌وکار گروه‌بندی کنید. قانون دامنه خالص، هماهنگی برنامه صریح و زیرساخت مانند HTTP و ذخیره پشت آداپتور باریک باشد. کامپوننت state و event را به UI تبدیل کند و مالک همهٔ مسئولیت‌ها نباشد.

هم پوشهٔ shared عظیم و هم انتزاع برای هر خط نامناسب است. رفتار مشترک را پس از روشن شدن قرارداد پایدار استخراج کنید. جهت import را اعمال و جزئیات قابلیت را تا حد امکان خصوصی کنید. monorepo بسته و ابزار را هماهنگ می‌کند، اما پیچیدگی گراف و انتشار دارد. برای تصمیم مهم ADR شامل زمینه، گزینه، تصمیم و پیامد بنویسید.

## خطاهای رایج

تزریق وابستگی فریم‌ورک لازم ندارد. wrapper که فقط نام همهٔ متدهای کتابخانه را عوض کند ممکن است بدون مرز مفید هزینه بسازد.

## تمرین و معیار پذیرش

ذخیرهٔ محلی پروژهٔ کار را با آداپتور حافظه‌ای جایگزین کنید، بدون تغییر اعتبارسنجی و گذار دامنه.

## راهنمای حل

در مرز ذخیره load/save تعریف، آداپتور را تزریق و استثنای ذخیره را از reducer دامنه خارج کنید.
