# 041 — احراز هویت و نشست

[English](./041_Lesson_English.md) · [مسیر دوره](../README_Persian.md) · [راهنمای اجرا](../RUNNING_Persian.md)

## مفهوم و سازوکار

احراز هویت هویت را مشخص و مجوزدهی عمل مجاز را تعیین می‌کند. نشست می‌تواند شناسهٔ opaque در cookie دارای Secure و HttpOnly باشد که سرور آن را بررسی می‌کند. SameSite و دفاع CSRF باید با ناوبری و embedding سازگار باشد. انقضا، ابطال و خروج علاوه بر حالت UI مسئولیت سرور هستند.

OAuth واگذاری دسترسی و OpenID Connect لایهٔ هویت است. جریان مرورگر معمولاً authorization code همراه PKCE و اعتبارسنجی سخت redirect دارد. backend-for-frontend می‌تواند token را از دسترس JavaScript مرورگر خارج کند، اما مسئولیت سرور دیگری اضافه می‌کند. JWT قالب token است، نه رمزنگاری یا سازوکار خودکار خروج. decode اعتبارسنجی امضا نیست.

## خطاهای رایج

token را log یا در URL ارسال نکنید و پس از خروج کش هویتی را قابل مشاهده نگذارید. طوفان refresh به هماهنگی نیاز دارد.

## تمرین و معیار پذیرش

رفتار بارگیری اولیه، خروج، انقضای نشست، منبع ممنوع و خروج موفق در دو تب را طراحی کنید.

## راهنمای حل

401 و 403 را جدا نگه دارید، refresh محدود را هماهنگ، نشست سرور را هنگام خروج باطل و تب دیگر را برای پاک کردن دادهٔ کاربر آگاه کنید.
