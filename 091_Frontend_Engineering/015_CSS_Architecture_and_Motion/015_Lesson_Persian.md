# 015 — معماری CSS و حرکت

[English](./015_Lesson_English.md) · [مسیر دوره](../README_Persian.md) · [راهنمای اجرا](../RUNNING_Persian.md)

## مفهوم و سازوکار

سازمان‌دهی CSS باید مالکیت و override را قابل پیش‌بینی کند. BEM از قرارداد نام، CSS Modules از محدودسازی نام کلاس در ابزار و utility از ترکیب قوانین کوچک استفاده می‌کند. هرکدام قابل استفاده است؛ ترکیب بدون مرز، سامانه‌های سبک‌دهی تکراری می‌سازد. reset و توکن عمومی را از قانون کامپوننت جدا کنید.

transition یک ویژگی را بین حالت‌ها تغییر می‌دهد و keyframe دنباله را تعریف می‌کند. حرکت برای توضیح تغییر وضعیت باشد؛ فهم محتوا وابسته به آن نباشد و prefers-reduced-motion رعایت شود. وقتی با طراحی سازگار است transform و opacity را ترجیح دهید و سپس اندازه بگیرید. nesting و :has می‌توانند کد واسط را کم کنند، اما پشتیبانی و خوانایی انتخابگر را بررسی کنید.

## خطاهای رایج

انتخابگر عمومی نباید همهٔ دکمه‌های ویجت دیگر را تغییر دهد. عنصر نامرئی متحرک را قابل focus رها نکنید.

## تمرین و معیار پذیرش

برای بخش بازشونده حالت باز و بسته بسازید، قانون کاهش حرکت اضافه کنید و مالک هر انتخابگر را بنویسید.

## راهنمای حل

اگر کافی است از details/summary بومی استفاده کنید. با transition غیرفعال هم وضعیت باز صحیح باشد و حرکت غیرضروری حذف شود.
