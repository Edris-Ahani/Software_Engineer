# 043 — کش، CDN و تحویل منابع

[English](./043_Lesson_English.md) · [مسیر دوره](../README_Persian.md) · [راهنمای اجرا](../RUNNING_Persian.md)

## مفهوم و سازوکار

کش مرورگر و CDN محدودهٔ متفاوت دارند. Cache-Control تازگی و اشتراک و ETag اعتبارسنجی شرطی را کنترل می‌کند. no-cache ذخیره را مجاز می‌کند ولی پیش از استفاده تأیید می‌خواهد؛ no-store درخواست عدم ذخیره است. فایل immutable با hash محتوا عمر طولانی می‌گیرد، اما HTML اشاره‌کننده به آن راهبرد به‌روزرسانی سازگار می‌خواهد.

کلید کش عمومی باید همهٔ بُعدهای مؤثر نمایش را دربر گیرد. Vary با سرآیند انتخاب می‌کند، اما تنوع زیاد hit rate را کم می‌کند. محتوای شخصی مدیریت private و جلوگیری از نشت میان کاربران می‌خواهد. فشرده‌سازی حجم انتقال را کم می‌کند، نه هزینهٔ parse. فقط منبع واقعاً بحرانی را preload و اتصال پیشاپیش را محدود کنید، چون اتصال بی‌استفاده منابع می‌گیرد.

## خطاهای رایج

HTML هویتی را تصادفی عمومی کش نکنید. کش service worker لایهٔ دیگری است و خودکار تابع تازگی HTTP نیست.

## تمرین و معیار پذیرش

برای index.html، JavaScript دارای hash، JSON پروفایل و فهرست عمومی محصول سیاست تحویل بنویسید و rollback را توضیح دهید.

## راهنمای حل

دارایی hashدار انتشارهای قبلی را حفظ، HTML را اتمی به‌روز، دادهٔ عمومی را طبق نیاز تأیید و کش مشترک پاسخ خصوصی را منع کنید.
