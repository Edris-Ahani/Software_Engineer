# 046 — ارتباط زنده و بازیابی اتصال

[English](./046_Lesson_English.md) · [مسیر دوره](../README_Persian.md) · [راهنمای اجرا](../RUNNING_Persian.md)

## مفهوم و سازوکار

polling خواندن تکراری HTTP، SSE جریان متن سرور به کلاینت با پشتیبانی اتصال مجدد مرورگر و WebSocket پیام دوطرفه است. WebRTC رسانه و کانال دادهٔ همتا همراه signaling و عبور اتصال فراهم می‌کند. براساس جهت، تأخیر، زیرساخت، هویت و بازیابی انتخاب کنید.

اتصال زنده ممکن است قطع شود، رخداد تکراری بدهد یا عقب بماند. id یا نسخهٔ رخداد بدهید، فاصله را تشخیص و در صورت نیاز از snapshot همگام کنید. buffer را محدود و نمایش را دسته‌بندی کنید تا نخ اصلی اشباع نشود. اتصال دوباره backoff و jitter می‌خواهد؛ نشان وضعیت باید تازگی کاهش‌یافته را بیان کند و دادهٔ قدیمی را جاری جلوه ندهد.

## خطاهای رایج

WebSocket خودکار قابل اعتمادتر از HTTP نیست. EventSource بومی در header هویت محدودیت دارد؛ token را برای جبران در URL نگذارید.

## تمرین و معیار پذیرش

نمونهٔ محدود SSE را اجرا، id رخداد را مشاهده و پس از رخداد سوم اتصال را ببندید؛ بازیابی رخداد ازدست‌رفته را طراحی کنید.

## راهنمای حل

رخداد را با id یا نسخه اعمال، تکراری را رد و در فاصلهٔ نسخه snapshot تازه بگیرید؛ اتصال را همیشه پاک‌سازی کنید.
