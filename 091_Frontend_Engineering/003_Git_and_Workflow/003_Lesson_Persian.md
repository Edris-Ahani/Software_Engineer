# 003 — گیت و جریان کار

[English](./003_Lesson_English.md) · [مسیر دوره](../README_Persian.md) · [راهنمای اجرا](../RUNNING_Persian.md)

## مفهوم و سازوکار

گیت در هر کامیت تصویری از فایل‌ها نگه می‌دارد. درخت کار، ناحیهٔ staging و تاریخچهٔ ثبت‌شده جدا هستند؛ پیش از افزودن فایل diff و پیش از کامیت diff ناحیهٔ staging را ببینید. شاخه تغییر را جدا می‌کند، اما فایل untracked تا زمان کامیت متعلق به شاخه‌ای نیست.

کامیت کوچک با هدف روشن، بازبینی، بازگردانی و یافتن خطای تاریخی را ساده می‌کند. merge ساختار شاخه‌ها را نگه می‌دارد؛ rebase هویت کامیت‌ها را تغییر می‌دهد و در تاریخچهٔ مشترک باید تابع سیاست تیم باشد. تعارض را با درک هر دو هدف حل و سپس بررسی‌های مرتبط را اجرا کنید. node_modules، خروجی ساخت و اسرار را نادیده بگیرید؛ کد، نمونهٔ تنظیمات و lockfile را ثبت کنید.

## خطاهای رایج

همهٔ تعارض‌ها را با انتخاب یک سمت حل نکنید و خصوصی بودن مخزن را مجوز ثبت رمز ندانید.

## تمرین و معیار پذیرش

در مخزن آزمایشی روی دو شاخه یک تابع را متفاوت تغییر دهید. merge کنید، تعارض را حل و رفتار نهایی را توضیح دهید.

## راهنمای حل

git status و git diff و git diff --cached را بررسی کنید. هر دو رفتار لازم را حفظ و خروجی قابل مشاهده را پیش از کامیت ارزیابی کنید.
